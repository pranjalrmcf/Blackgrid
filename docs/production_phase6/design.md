# Phase 6 implementation proposal and frozen pilot

Authorized 23 October 2026. vLLM is explicitly out of scope. Paid-provider execution and new cloud/GPU resources are not part of this work.

Acceptance: a secure automatically refreshing operator dashboard plus reproducible, resource-bounded synthetic concurrent-client measurements, with exact accounting for completed, rejected, failed and censored work. Scientific/agent tools, paid ledgers and existing real-data configuration stay intact.

The existing single-worker API and Phase 5 metrics are the base. Add a short-lived in-memory, Secure/HttpOnly/SameSite=Strict operator session for browser use, static same-origin assets and five-second bounded polling. No credentials in URLs, generated HTML or local storage. Browser sessions are restricted to dashboard routes; they cannot submit jobs or replace API bearer authentication. Reject cross-origin state changes and retain no-store/CSP and rate controls.

Benchmark Locust in a separate optional build target and isolated test service/volume, not the user's live service or retained billing database. No production provider key, real data, held-out truth or prediction/research evidence is mounted in the benchmark service. All model traffic remains deterministic offline mock, with a separately labeled bounded latency fixture. A direct mock fault harness measures transient/schema/uncertain failures; it does not pretend to measure real inference.

The original frozen protocol is `protocols/production_phase6_v1.json`, registered before running the pilot. After inspecting its incomplete behavioral analyses, v2 explicitly records that inspection and the narrow synthetic event adapter/mock latency correction; the v1 protocol and results remain immutable. Generate the five families at 100/300/1,000 nodes within the existing caps. Initial API concurrency stages use an explicitly labeled 100-node input. Direct graph checks cover the other families/sizes under time limits; large sizes are generated and validated before execution, never substituted after seeing findings. Node membership/generator truth and temporal future events are kept outside runtime mounts/prompts. Record generator/manifest/event/config hashes, versions, seeds, dataset scope, hardware, observed concurrency, timing samples, resource series and cost. These are exploratory engineering results, not graph-independent scientific significance or production-capacity claims.

Synthetic event provenance uses an explicit versioned synthetic source marker, pinned manifest and existing `GraphRecord` synthetic contract; default CollegeMsg loading and stored configuration schemas remain unchanged. New synthetic benchmark configurations explicitly reduce null/restart/sensitivity budgets, preserve caps and are never used to reinterpret CollegeMsg evidence.

Locust records sanitized route labels, per-request samples and per-job creation/start/finish/result verification. Count offered, accepted and rejected submissions separately. Use first-start queue wait and creation-to-terminal completion for each job, including drain time; unfinished jobs are censored rather than omitted. Compute benchmark quantiles from raw benchmark samples, not rolling operations summaries. Keep API-only probes, tools, mock-provider fixture, agent and full-workflow categories distinct. Stop on the registered resource, health/error, storage, time and output limits. Queue/rate saturation is measured and reported, not hidden by raising limits.

Complexity is moderate: browser authentication and benchmarking/accounting are the main risks. Changes are limited to API/dashboard/session modules and assets, monitoring resources, an explicit synthetic-source adapter, optional mock fixture, benchmark generator/Locust/orchestration scripts, benchmark-only dependencies/build stages, tests and docs. No external collector or extra production service is needed. Verification includes browser access/CSRF/session-expiry checks, truth isolation/provenance, known numerical quantiles/nested timing, request/job reconciliation, stop conditions, all existing scientific regressions and clean-image offline execution.

Limits: retain target 1 CPU/2 GiB/128 PIDs, at most one active/eight queued analyses. Limit the separate generator to 0.5 CPU/512 MiB and 128 PIDs, total pilot to 30 minutes, each stage to 240 seconds and fixed output/sample caps. Mock timings/quality do not establish real provider performance. Dashboard samples show their update time and stale state. vLLM, real-LLM load, graph-limit expansion, multiple production workers and later-phase optimization remain out of scope.

Rollback: restore `blackgrid:phase5` with the same current production volume/registry; browser sessions disappear on restart. Stop the isolated benchmark containers without deleting their evidence. Keep the current paid ledger and scientific artifacts; never restore an older spend snapshot. The benchmark-only dependency group is excluded from production images.
