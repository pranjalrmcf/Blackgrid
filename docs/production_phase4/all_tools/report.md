# Phase 4 follow-up — automatic API routing for all 18 tools

Date: 22 October 2026. Completed: all 18 registered tools are integrated, the cumulative image is built and deployed, and offline/service acceptance passed.

## Authorized change and compatibility

The user authorized exposing all registered tools through normal question submission and building the cumulative Docker image. The initial API forced `--family community` and exposed only community summary fields/progress labels. The existing scientific controller already supported six analysis families and 18 registered tools, including LLM semantic family/tool choice. Forecast factories expected a shared local evaluation folder, and research expected the saved synthetic run at a repository path; isolated API jobs could not find these sources.

New jobs use `--family auto`; all 18 tools have static progress labels and an authenticated capability catalog; results use analysis-specific aggregate allowlists and the existing closed evidence-bound claim vocabulary. Partial/abstained investigations expose a minimized result instead of a misleading community summary. Existing queued jobs retain community routing on schema migration; old idempotency digests and budgets are preserved. Model/prompt templates, scientific methods, experimental protocols, original LLM role sequence and provider retry/accounting remain unchanged. A separate explicit API-only saved-belief portability profile was added after the cross-platform failure described below; the original benchmark verification default stays strict. The family value in a planner request changes for new API jobs, so token counts are allowed to differ from the old forced-community request; scientific comparisons still require exact numerical/call-count/cost parity.

Private typed evidence bindings are pinned at admission and captured in the existing scientific input/checkpoint identity. The forecast factory accepts these optional pinned paths, checks all file hashes and the event-source hash, and retains its existing full-history cutoff/horizon/candidate semantics. The research binding retains manifest/artifact verification and uses explicit read-only SQLite observation reads. Original host CLI behavior without a binding is preserved. No additional service, database, dependency or external resource is introduced. Both `pyproject.toml` and `uv.lock` are unchanged.

The build remains an allowlisted private-data-free image. Existing saved evidence is mounted read-only at runtime, including only the prediction aggregate/freeze files rather than arrays/held-out labels. Research reads its saved synthetic artifacts; it does not run new observations or estimate real causal effects. Existing auth, tenant isolation, CPU/memory/process limits, deadlines, cancellation, network-denied workers, idempotency, safe mock recovery and uncertain-live holds remain active. See [the catalog and operator guide](../../api_tools.md).

## Limits and rollback

The controller chooses a compatible tool set for one analysis; it still rejects invalid/mixed plans and unsupported causal/calibrated-probability claims. Descriptive node/pair rankings stay local; the API returns aggregate results and checked statements. Forecasts use all validated history at the registered cutoff, not just the first-window graph context, and may refit existing fixed model specifications. They can take longer and use more memory; no latency improvement is claimed.

Saved synthetic research does not establish real-data calibration or identified causal effects. Missing/changed evidence yields an explicit incomplete/refused outcome, not invented findings. The single-host queue and independent legacy-ledger limitations remain as documented in Phase 4. An operator must keep the pinned source files mounted for recovery; do not restore an older spending ledger over newer charges.

Rollback retains `blackgrid:phase4` and its existing state-volume backup. Stop/inspect active work before changing the image, retain the newest database and all reservations, and review new auto-routed queued jobs before allowing an older adapter to execute them. No image registry publication or Git commit was requested for this follow-up. Phase 5 remains unapproved.
