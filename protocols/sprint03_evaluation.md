## Data and separation

Generate 24 new graph instances, IDs val-001 through val-024. Structural families: strong planted blocks, weak planted blocks, random fixed-edge graphs, uneven degrees, disconnected graphs, and masked observations, three instances each. Case i (1..18) has generator seed 1001 + 100*(i-1). Six additional independent random graphs carry invalid-method (odd case indices) or causal (even) requests, with seeds 8001..8006. All seeds are outside development ranges. The 100-step spacing prevents shared component seeds in the disconnected generator (which uses seed, seed+1, seed+2, seed+3). This corrects the unexecuted draft before inspecting validation outcomes. Hash-check graph overlap against development; distinct seed ranges alone do not prove distinct structures.

Frozen parameters per family: strong SBM (3 blocks x 10, p_in=.6, p_out=.03); weak SBM (2 x 20, .18, .12); random G(n=30,m=60); uneven degrees (n=60,max_weight=25,exponent=.8,min_weight=3, largest component only); disconnected (4 pieces x 8 nodes,12 edges each); masked SBM (3 x 10,.35,.02,30% unknown pairs); invalid requests use G(n=20,m=35). Families are assigned in that order in blocks of three. These parameters resemble development fixtures; only instances are fresh. No held-out-family generalization claim is made.

The planner receives only a neutral question, request, graph and GraphRecord. Generator family, parameters, planted labels, hidden edges, and expected behavior stay evaluator-only. A human registry containing answers must never enter prompts. Do not generate/open benchmarks/sealed.

## Method comparison

Run on the 18 structural validation graphs. Use NetworkX Louvain and a real igraph/leidenalg CPU adapter. Leiden uses RBConfigurationVertexPartition at resolution 1 (the modularity-equivalent objective), two refinement iterations, five seeded restarts. Both scores are recomputed through NetworkX modularity. Preserve isolated nodes, edge semantics and node mapping during conversion. Validate partition coverage, disjointness, and induced-community connectivity.

Per graph use master seeds 31, 47 and 83, 99 shared degree-preserving randomized graphs per seed, and identical restart count on observed and null graphs for each optimizer. Use the existing double-edge swap implementation and reject unsuitable null samples under the existing failure/variation thresholds. Report Q, null mean, delta Q, Monte Carlo p, runtime, partition connectivity and seed stability. Matching restarts does not equate optimization effort; disclose implementation/refinement differences. Record finite-swap sampling limitations. Apply the same largest-component robustness logic as the original protocol to disconnected inputs; overall verdict requires both relevant analyses.

No default selection by significance. Keep Louvain the default during Sprint 3. Any later switch needs a documented decision using connectivity, stability, runtime and accuracy/coverage, not whichever p-value looks better. P-values are exploratory; no multi-method confirmatory claim is made. Backend unavailability is explicit and must not be counted as a successful Leiden run.
