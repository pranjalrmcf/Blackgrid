# API saved-belief portability profile v1

Registered 22 October 2026 after observing that a hash-verified Windows-created saved research bundle fails the Linux verifier's exact posterior-summary equality. The mismatch was inspected before this compatibility profile was introduced; this is not a new benchmark or a revision of Sprint 7's experimental thresholds/results.

Profile identifier: `api-beliefs-portability-v1`. It is explicit in an API job's pinned research binding and existing checkpoint identity. The default Sprint 7 verifier remains exact unless this profile is explicitly requested by the API binding.

All manifest/artifact hashes, observation count, model identity/specification, target, interval label, method names, posterior alpha/beta parameters and dictionary/list structure must agree exactly. Only the independently recomputed derived posterior `mean`, two `credible_interval_95` values and eleven `predictive_block_10` probabilities for methods A/B may differ. Each must remain a finite float in [0,1] and satisfy `abs(actual-recorded) <= 1e-12 + 1e-12 * max(abs(actual),abs(recorded))`. No other field has a tolerance. Nonfinite values, wrong types/lengths, changed counts/parameters, missing keys, unknown profiles and larger differences fail closed.

The fixed tolerance is a numerical portability bound for SciPy-derived decimal probabilities, independent of a hypothesis/decision threshold or observed graph outcome. It cannot change the saved scientific result, authorize new observations, reconcile changed artifact hashes, relabel intervals or establish real-data calibration. Saved files are never rewritten or rounded. API tools report the original pinned aggregate values after independent verification. Verification tests must cover strict-default rejection of drift, profile acceptance of tiny derived-value drift, and rejection of parameter/count/hash/large-value changes. This profile is not permission to relax any frozen benchmark acceptance gate.
