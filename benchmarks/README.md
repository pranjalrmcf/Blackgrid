# Benchmarks

| Split | IDs | Seed range | Location | Status |
|---|---|---|---|---|
| Development | `dev-001` … `dev-999` | 1–999 | generated by `blackgrid.benchmark.dev_cases()`; public listing in `dev/registry.json` | 8 cases (Sprint 1, Day 4) |
| Validation | `val-001` … | 1,000–9,999 | not yet created | reserved |
| Sealed test | `test-001` … | 100,000–999,999 | `benchmarks/sealed/` (git-ignored) | **reserved; do not generate** |

The ranges are disjoint so a seed from one split can never regenerate a graph from another. `blackgrid.benchmark.split_of` and `seed_allowed` enforce this.

## Rules

- **Answer keys are evaluator-only.** Each case has a public half (`PublicCase`, the graph, and the `GraphRecord`) and a private half (`CaseKey`, `EvaluatorTruth`). Planner, critic, and report code receive only `DevCase.planner_view()`.
- **Development cases are engineering fixtures.** They exist to build and debug the harness. Results on them are not evidence that any component works.
- **The sealed test set is generated only after freezing.** Prompts, evaluators, model identifiers, thresholds, and budgets must be frozen and recorded in the decision log first. Its instances, seeds, and keys live under `benchmarks/sealed/` and are never committed or exposed to agents. Any correction after inspecting test results requires a new test set or explicit exploratory labelling.
- **Neutral IDs.** Case IDs and questions must not reveal the generator family or the expected answer.
